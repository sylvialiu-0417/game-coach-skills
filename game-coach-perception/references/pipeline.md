# 观察提取流程

## 统一时钟与证据

为每个媒体片段保存原文件 ID、起止时间、全局偏移、视角和采样/裁剪设置。视频与音频先对时；事件 API 与媒体按同一会话时钟对齐。输出的 `t0_ms/t1_ms` 统一为本场会话相对时间，并允许回到原始帧、音频片段或 API 事件。跨片段重叠的同一事件合并为一个观察，证据引用可保留多个。

## 识别与核验

对数值和 UI 文本可用 OCR；对对象及连续运动可用 CV/跟踪；对语义复杂、需要多帧理解的内容可用 VLM/视频模型。选择依据是该游戏标注集上的实际错误、延迟和成本，不把模型名称写死。若两个识别器对关键值冲突，标记 `conflict` 并请求进一步证据；高风险实时建议不等待不确定识别。

3D 场景先标注相机视角、可见区域、遮挡和对象身份。画面中的“左侧有脚步声”只证明听到方向线索，不证明敌人确切坐标；单帧中看不见对象也不证明其不存在。多视角录像可帮助复盘，但对局提示仍按玩家可见视角限制输出。

观察层只给状态和事件，不给行为优劣或战术动作。若来源支持精确结构化数据，直接记录其事件 ID；若视觉识别产生估计值，注明方法、置信区间或已校准分数、失效条件。没有校准集时使用 `inferred` 或 `unknown`，不要把任意概率阈值当作通用规则。导出的预标注保留 `machine_draft` 状态，交专家标注流程查看原媒体后复核，不能直接作为金标准答案。
