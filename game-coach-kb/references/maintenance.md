# 知识维护与版本发布

## 反馈到变更

玩家、专家或自动监控可提交反馈，包含原问题、工具轨迹、版本链、证据 ID 和建议输出。运营先按 [接入与补强](onboarding.md) 的六类原因定位故障；知识库中已有正确条目时，优先修检索或决策，不重复加文档。无法复现的反馈保留为待观察，不直接改线上库。

## 版本变更

规则更新、资料纠错或来源失效时，比较新旧版本，列出受影响条目、策略引用、教练能力和评测题。对新增或改写内容确认来源、模式、有效期和适用条件；冲突交给领域负责人裁决。回归评测应覆盖旧版本隔离、当前版本检索、按游戏隔离、回退和恶意内容。

## 发布状态机

`proposed → reviewed → evaluated → published`。发布服务验证审批身份、评测门槛与快照完整性，原子切换当前快照；异常时回滚到已知可用快照，并保留审计记录。Skill 可准备差异、分析影响、解释评测结果，不能凭文本宣称审批通过或直接改生产库。

## 持续监控

按游戏、规则版本、教练、任务和知识类型看检索空结果、回退率、证据冲突、错误建议、状态过期、延迟和玩家关闭提示。高回退率可能是合理谨慎，需结合人工审核判断；低回退率也可能意味着编造。抽样复核和失败轨迹进入下一版独立测试集，避免只在旧样本上优化。
