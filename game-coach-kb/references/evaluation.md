# 游戏适配与 Skill 评测规范

评测目标是确认 SOP 在**拟接入的目标游戏**中是否有效。每个游戏分别提供适配配置与真实样本；虚构示例和其他游戏的成绩不能替代该游戏的验收。固定同一模型、知识快照、工具、状态输入与延迟预算，对比无 Skill、旧版 Skill 和本版 Skill；保留未参与调试的独立测试集。

## 先测触发 再测执行

用 [26 条触发案例](../evals/trigger-cases.jsonl) 分开测正例、反例和边界例。正例漏触发会让教练跳过知识检查；反例误触发会干扰普通攻略创作或误把发布动作交给玩家侧。边界例先问清是否处在已接入教练场景，不把模糊请求硬判为正例。记录精确率、召回率及每条错误，不使用“静态文件通过”替代真实触发测试。改变 description 后固定同一模型和用例复测。

## 四组执行样本

1. **接入诊断**：已有知识库分别缺版本、缺来源、检索漏召、状态接口缺失。看能否定位到正确改进层，而非一律“补知识”。
2. **按游戏适配验证**：在每个拟接入游戏中分别跑规则问答、条件策略、无状态回退、复盘与训练计划，并由领域专家制定该游戏的判据。包内两类虚构游戏用于展示契约，不代表已在真实游戏验证。
3. **Agent 轨迹**：检查路由、过滤、工具参数、证据选择、状态新鲜度、输出和回退。只看最终文案会漏掉错误工具调用。
4. **维护与安全**：版本更新、冲突、来源失效、权限越界、提示注入、审批前发布、回滚。硬性失败应阻止上线。

## 分层指标

| 层 | 指标 | 观察点 |
| --- | --- | --- |
| 触发与路由 | 触发精确率/召回率、游戏和教练路由正确率 | 不该调时不调、不同游戏的数据互相隔离 |
| 检索 | 当前版 Recall@k、来源可追溯率、冲突识别率 | 已发布且适用的证据进入候选 |
| 决策 | 证据支持率、条件满足率、正确回退率、错误建议率 | 事实与策略前提分开核验 |
| 复盘 | 片段时间准确率、重复事件率、诊断证据回链率 | 不把模型解释当成已观察事实 |
| 操作 | 工具轨迹正确率、越权调用数、发布/回滚成功率 | 管理端有确定性审批 |
| 体验 | 延迟、重复提示、关闭率、理解/采纳 | 各游戏、各教练分层观察 |

严重事实错误、不同游戏的数据串库、利用隐藏信息、越权发布或在缺关键状态时给确定的高风险指挥为硬性失败。阈值需由具体游戏团队事先定，不能以总平均分掩盖某一游戏退化。

## 验证顺序

先跑包结构和虚构样本，确认契约可执行；再用各游戏真实知识与匿名轨迹做离线配对评测。若接入感知层，分别测观察准确性和教练判断，保留“给定正确观察时教练能否判断”的对照；否则端到端错答无法定位。专家盲评答案与工具轨迹；上线前影子运行，只记录不展示；小流量发布后观察体验指标，并按版本和游戏切片。若新游戏无可用状态工具，仅验收知识问答和条件式建议，不把局内提示当作已通过。

`evals/cases.jsonl` 和 [输入输出示例](../examples/decision-examples.md) 是设计检查素材，不证明模型实际能力。可参考 [LangSmith 离线与在线评测](https://docs.langchain.com/langsmith/evaluation-types) 和 [Ragas 工具调用指标](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/agents/) 设计自动评分；战术适用性仍需相应游戏专家检查。每次改动保留运行配置和版本链，保证可复现。
